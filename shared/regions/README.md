# Mainland China location dataset

Vendored and converted `dist/code/pca.json` from [kk-418/cn-division](https://github.com/kk-418/cn-division), version `2026.0.1`, commit `88f2021ea21769bdb95d93699d8a625fcd9165ef` dated **2026-09-02**. Upstream declares its source as the [Ministry of Civil Affairs place-name interface](https://dmfw.mca.gov.cn/interface.html), with some explicitly maintained supplemental functional areas. Included MIT license is in `LICENSE`; source URL, checksum, revision and counts are in `metadata.json`. This is a pinned third-party snapshot, not a guarantee of exhaustive current official coverage.

This replaces the initial NBS 2023-06-30 statistical dataset. It includes 31 mainland provinces, 371 raw city nodes (municipality groups are combined in the UI) and 2,935 area nodes. Statistical development zones are not all administrative districts; fewer nodes than the old snapshot does not by itself mean missing counties. Refreshed examples include Sansha's 西沙区/南沙区 and 米林市, plus town/street options for cities without districts. There is no nationwide street/village or salon-coordinate dataset.

The direct MCA request failed from this development environment on 2026-10-03. The pinned open-source download succeeded. Runtime forms and backend validation use the same local snapshot and make no dependency on that public interface. No paid map provider or key is required for this dataset.

`index.ts` is shared by the browser, Web API and Convex validation. Codes are strings: province 2 digits, city 4 digits (directly administered counties 6), area 6 digits (towns/streets in cities without districts 12). Preserve source codes; do not truncate town codes or validate hierarchy by string prefixes alone. Municipalities combine district/county statistical groups into one city. Directly administered counties are selected by name rather than a statistical grouping label.

Every save derives canonical names and stores `countryCode`, region codes and `regionDatasetVersion`. Input codes must resolve to one valid hierarchy. The location denotes the salon, not an arbitrary multi-region service radius. Detailed address remains separate. No coordinates are inferred from region centers.

Optional salon pins now use browser geolocation or Leaflet/OSM, in WGS84, with source, applicable GPS accuracy and server confirmation time recorded privately. Pin confirmation is by the applicant, not proof of a verified address. Geocoding and customer matching remain future work. If another map provider is added, retain its coordinate system (e.g. GCJ-02 versus WGS84), provider/place ID and verification metadata. Keep map secrets server-only and convert coordinates consistently before measuring distance.

To update, review a newer upstream revision, change the pin/version in `scripts/update-regions.mjs`, and run `pnpm regions:update`. The script validates structure, code formats, uniqueness, mainland scope and minimum coverage before writing, saves provenance, and reports added/removed/renamed areas. Run location/application regression checks and review the diff; never run refresh automatically during build or user requests. Plan explicit reconciliation for existing records, especially the old 9-digit versus new 12-digit town codes; do not silently move saved salons to another area. Updates still need review and may omit renamed or newly established regions.
